# data/reference-library/

مكتبة الاستماع المرجعية (القرار 9.2) — 25 نغمة مفردة + 8 تسجيلات مقامات
كاملة، بصوت ناي حقيقي. **إداري بحت** — لا علاقة برحلة المتدرب التفاعلية،
مصدرها صفحة الخبير (`src/ui/admin/expert-intake/`).

## الحالة الحالية: فارغة، جاهزة للاستيراد

`audio/` فارغ حاليًا، و`manifest-data.js` يُصدِّر مصفوفتين فارغتين. صفحتا
#2 و#4 تتعاملان مع هذا بحالة "لا تسجيلات بعد" — لا شيء يُكسَر بغياب الملفات.

## كيف تُضاف الملفات فعليًا لاحقًا

1. جلسة خبير كاملة عبر صفحة الخبير → تنزيل WAV + بيان JSON تلقائيًا.
2. إرسال المجلد للمالك خارج الموقع.
3. وضع ملفات WAV داخل `audio/` (بنفس الأسماء من صفحة الخبير حرفيًا).
4. إضافة سطر مطابق في `manifest-data.js` لكل ملف (id/filename متطابقان
   حرفيًا مع اسم الملف وid الأصلي من `expert-intake-data.js`).

## لماذا JS module لا JSON يُجلَب بـ fetch()

الصفحات المستهلِكة (#2، #4) يجب أن تعمل عبر `file://` بلا خادم (نفس وعد
المنصة الأساسي، مُختبَر في `build/tests/build-output.test.mjs`) —
`fetch()` لملف JSON محلي يُحجَب بقيود CORS تحت `file://` في أغلب
المتصفحات. وحدة JS مُجمَّعة وقت البناء (نفس نمط `maqam-data.js`) تتفادى
هذا القيد بالكامل.

## مسار ملفات الصوت: ثابت المصدر، يُعاد كتابته وقت الدمج

الصفحات تستورد المسار الأساسي من `src/ui/shared/reference-audio-path.js`
(قيمة تطوير: `../../../../data/reference-library/audio/`) — `build/build.mjs`
يعيد كتابة هذا المسار بالضبط في مخرجات كل صفحة مدموجة (`../data/reference-library/audio/`,
لأن `dist/` بنية مسطَّحة مختلفة العمق)، **ثم** ينسخ `audio/` فعليًا إلى
`build/dist/data/reference-library/audio/`. نفس أسلوب معالجة مسار صفحة #3
تمامًا (`buildRedirectPage`) — لا حل جديد، امتداد لنمط موجود.
