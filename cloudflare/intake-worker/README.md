# cloudflare/intake-worker/ — نقطة استقبال JSON (استثناء القرار 4)

الاستثناء الوحيد لمبدأ "لا خادم" (القسم 4 من سجل القرارات): نقطة استقبال
بسيطة على Cloudflare Workers/KV لاستقبال بيانات معايرة مُصدَّرة من صفحة #6
(أرقام قياس فقط، لا صوت)، بمفتاح فريد لكل عازف (رمز المزامنة من صفحة #7).

## الحالة: الكود مكتوب ومُختبر محليًا بالكامل — **لم يُنشَر بعد فعليًا على Cloudflare**

⚠️ **مهم — لماذا لم يُنشَر:** هذي البيئة (سندبوكس تنفيذ Claude) ليس لديها
وصول شبكي لنطاقات Cloudflare (`api.cloudflare.com` وما شابه غير موجودة في
قائمة النطاقات المسموحة)، ولا تملك بيانات اعتماد حساب Cloudflare الخاص
بك. **النشر الفعلي خطوة يدوية يجب أن تنفّذها أنت** باستخدام حساب Cloudflare
الخاص بك — الخطوات كاملة أدناه.

## البنية

| الملف | الدور |
|---|---|
| `worker.js` | كود الـ Worker الفعلي: `validatePayload` (تحقق بنيوي من الحمولة)، `extractPlayerId` (استخراج معرّف العازف من المسار `/submit/{playerId}`)، ومعالج `fetch` الكامل الذي يتحقق من الطلب ويخزّن في KV. |
| `worker.test.mjs` | 16 اختبار وحدة خالص بـ Node (لا Miniflare/wrangler) — يستخدم `Request`/`Response`/`URL` المدمجة في Node (نفس الواجهات القياسية لـ Workers) وربط KV وهمي بسيط. يغطي كل حالات الرفض (405، 400 بأنواعه، 500 عند غياب ربط KV) والحالة الناجحة (200، تخزين تراكمي صحيح). |
| `wrangler.toml` | قالب تهيئة — يحتاج تعديل `kv_namespaces[0].id` (ومسار `routes` اختياريًا) بقيم حسابك الفعلية قبل النشر. **لا سرّ أو مفتاح API مخزَّن هنا.** |

## قرارات تقنية

- **تخزين تراكمي، لا استبدال.** كل إرسال يُخزَّن بمفتاح `player:{playerId}:{receivedAtMs}`
  منفصل، بدل الكتابة فوق آخر إرسال — يطابق مبدأ "لا حذف تلقائي" المطبَّق
  على التصدير المحلي (القرار 4)، ويمنع فقدان بيانات عند إرسالين متزامنين.
- **نطاق ضيق مقصود.** استقبال وتخزين فقط — لا قراءة/استرجاع، لا حذف، لا
  معالجة أو تحليل داخل الـ Worker. القرار 4 ينص صراحة أن هذا الاستثناء
  "لا يُوسَّع... لأي غرض آخر إلا بفتح نقاش الحسابات/الاشتراكات (القسم 6)
  صراحة" — لذلك تعمّدت إبقاءه أضيق ما يمكن.
- **معرّف العازف مصدر تتبّع لا مصادقة تشفيرية.** القرار 4 يطلب "رمز تعريف
  خاص بكل عازف... لتتبّع المصدر ومنع الإرسال العشوائي" — لا يطلب توقيعًا
  أو تشفيرًا. `playerId` هو نفسه المعرّف المحلي المُولَّد في صفحة #7
  (`crypto.randomUUID()`)، طويل بما يكفي (36 حرفًا) ليكون تخمينه العشوائي
  غير عملي، لكنه ليس حدًّا أمنيًا صارمًا بالمعنى التشفيري.

## خطوات النشر اليدوية (تحتاج حساب Cloudflare الخاص بك)

### 1. تثبيت وتسجيل الدخول لـ wrangler

```bash
npm install -g wrangler
wrangler login   # يفتح متصفحًا لتسجيل الدخول لحساب Cloudflare الخاص بك
```

### 2. إنشاء KV namespace

```bash
cd cloudflare/intake-worker
wrangler kv:namespace create MIRAN_INTAKE_KV
```

هذا يطبع `id` فعليًا — انسخه والصقه في `wrangler.toml` مكان
`REPLACE_WITH_ACTUAL_KV_NAMESPACE_ID`.

### 3. (اختياري) ربط سب دومين فعلي

إن أردت رابطًا على دومينك الخاص (مطابقةً لنص القرار 4 "سب دومين من دومين
المالك") بدل رابط `workers.dev` الافتراضي: أضف الدومين لحساب Cloudflare
إن لم يكن مضافًا، ثم فعّل سطر `routes` في `wrangler.toml` بقيم دومينك
الفعلية. بلا هذا السطر، `wrangler deploy` يعطي رابط `*.workers.dev` مجانيًا
يعمل فورًا — كافٍ للاختبار أو حتى الاستخدام الفعلي إن لم يكن السب دومين
المخصَّص أولوية.

### 4. النشر

```bash
wrangler deploy
```

يطبع رابط الـ Worker الفعلي (إما `*.workers.dev` أو دومينك المخصَّص إن
فعّلت `routes`). **انسخ هذا الرابط** — ستحتاجه في صفحة #7 (الإعدادات
والمزامنة) كحقل "رابط نقطة الاستقبال".

### 5. اختبار يدوي سريع بعد النشر

```bash
curl -X POST "https://YOUR-WORKER-URL/submit/test-player-1234567890" \
  -H "Content-Type: application/json" \
  -d '{"samples":[{"pitchHz":293.5,"fingering":"ري","register":"قرار","toleranceCents":12}]}'
```

يجب أن يرجع `{"ok":true,"receivedAtMs":...}` بحالة 200. تحقق من KV عبر
`wrangler kv:key list --namespace-id=YOUR_NAMESPACE_ID` لرؤية المفتاح
المخزَّن فعليًا.

## اختبار الكود قبل أي تعديل مستقبلي (بلا نشر، بلا حساب Cloudflare)

```bash
node cloudflare/intake-worker/worker.test.mjs
```

  توفر الإنترنت + إعادة محاولة عند الانقطاع) — انظر
  `src/ui/pages/07-settings-sync/README.md` للتفاصيل، هذا الجزء مبني في
  نفس هذي المرحلة أيضًا لكنه موثَّق هناك لا هنا.
- Rate limiting فعلي على مستوى Cloudflare (متاح كإعداد في لوحة تحكم
  Cloudflare نفسها، خارج كود الـ Worker) — لم يُطلب صراحة بعد.
- أي واجهة لقراءة/استرجاع البيانات المخزَّنة من KV — خارج النطاق الضيق
  المقصود لهذا الاستثناء (انظر "قرارات تقنية" أعلاه).
