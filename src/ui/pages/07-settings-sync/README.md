# 07 — الإعدادات + المزامنة

## ⚠️ حالة نائمة (القرار 9.6) — غير مُدرَجة بالتنقّل الحي

**اعتبارًا من القرار 9.6 في سجل القرارات، هذي الصفحة أُزيلت من `nav.js`
ومن روابط الصفحة الرئيسية — لا رابط لها من أي مكان حي بالمنصة.** السبب:
نقطة استقبال Cloudflare (استثناء القرار 4) مصمَّمة لتغذية "متوسط جماعي
مرجَّح بين كل العازفين" (القرار 2)، وهذا يفترض مجتمع متدربين مركزي غير
موجود حاليًا (النظام محلي فردي بحت).

**الكود هنا لم يُحذَف — باقٍ بالكامل، نائم فقط.** يُعاد ربطه بالتنقّل الحي
تلقائيًا عند تنفيذ القسم 6 (الحسابات/الاشتراكات) فعليًا لاحقًا. الرابط
المباشر (`src/ui/pages/07-settings-sync/index.html`) لا يزال يعمل فعليًا
لو زاره أحد مباشرة — فقط لا رابط ظاهر إليه.

---

نقل البيانات، إعدادات السماحية، كود المزامنة. يحمل معرّف المستخدم المحلي
بشكل صريح هنا تحديدًا (القسم 7، تحصين بيانات القسم 6). **الآن تدير أيضًا
الإرسال الشبكي الفعلي لنقطة استقبال Cloudflare (استثناء القرار 4).**

## الحالة: مدموجة فعليًا بالكامل — كود المزامنة، إعدادات السماحية، وإرسال شبكي فعلي (تلقائي + إعادة محاولة عند عودة الاتصال)

## البنية

| الملف | الدور |
|---|---|
| `index.html` | غلاف HTML، يحمّل `settings-sync-page.js` كوحدة ES. |
| `local-user-id.js` | معرّف المستخدم المحلي (كود المزامنة) — كما في المرحلة السابقة. |
| `intake-sync.js` | **جديد.** الجانب العميل من استثناء القرار 4: `getEndpointUrl`/`setEndpointUrl` (تخزين محلي لرابط نقطة الاستقبال، مفتاح `miran_intake_endpoint_url_v1`)، `attemptSubmit` (محاولة إرسال واحدة عبر `fetch`)، و`SyncManager` (يدير محاولة فورية + تسجيل إعادة محاولة تلقائية عند حدث `online` إن فشلت المحاولة الأولى بسبب انقطاع شبكي — نص القرار 4 حرفيًا: "إرسال تلقائي عند توفر الإنترنت... إعادة محاولة تلقائية في الخلفية عند الانقطاع"). |
| `settings-sync-page.js` | يستدعي `getOrCreateLocalUserId()`، يعرض حدود السماحية، ويبني قسم "نقل البيانات": حقل رابط نقطة الاستقبال (اختياري تمامًا، فارغ افتراضيًا)، زرَّي "حفظ" و"أرسل الآن"، وعرض حالة آخر مزامنة. يستورد `rebuildStore`/`buildExportPayload` من `../06-library-export/export-payload.js` (نفس الحمولة المُصدَّرة يدويًا في صفحة #6 — مصدر حقيقة واحد). إرسال تلقائي عند تحميل الصفحة **فقط** إن كان رابط مُهيَّأ مسبقًا. |
| `tests/page-smoke.test.mjs` | 10 اختبارات Playwright دخان (كانت 5، أُضيف 5): تدفق كامل — بلا رابط (خامد تمامًا، بلا أي طلب شبكي)، حفظ رابط وهمي + إرسال ناجح (تحقق فعلي من الطلب المُعترَض عبر `page.route`: المسار `/submit/{المعرّف}`، الحمولة تحتوي `samples`)، فشل شبكي → حالة "غير متصل"، إعادة محاولة تلقائية حقيقية عند حدث `online` بلا أي تدخّل يدوي، وزر "أرسل الآن" بلا رابط لا يُطلق أي طلب شبكي إطلاقًا. |

## قرارات تقنية اتُّخذت في هذي المرحلة

- **لا رابط افتراضي مُضمَّن في الكود.** النشر الفعلي لنقطة الاستقبال خطوة
  يدوية يجب أن ينفّذها المالك بحسابه الخاص على Cloudflare (بيئة تنفيذ
  Claude ليس لديها وصول شبكي لنطاقات Cloudflare ولا بيانات اعتماد الحساب
  — انظر `cloudflare/intake-worker/README.md`). قبل إدخال الرابط يدويًا،
  الميزة خامدة بالكامل: لا محاولات إرسال، لا مستمعات شبكة مُسجَّلة.
- **حمولة التصدير مُستخرَجة لملف مشترك جديد** (`../06-library-export/export-payload.js`)
  بدل تكرارها هنا — أول ملف يشاركه فعليًا صفحتان مختلفتان (#6 و#7) لنفس
  منطق إعادة بناء المخزن وبناء الحمولة، بعد أن كانت هذي الدالة معرَّفة
  محليًا فقط داخل `library-page.js` (صفحة #6).
- **إعادة المحاولة عبر حدث `online` لا عبر مؤقّت متكرر (polling).** أبسط،
  أدق توقيتًا (يُطلَق فورًا لحظة عودة الاتصال الفعلية بدل انتظار دورة
  التحقق التالية)، وأقل استهلاكًا للبطارية/الموارد من `setInterval` دائم.
- **إعدادات السماحية لا تزال عرضًا فقط** — لم يتغيّر من المرحلة السابقة،
  نفس التبرير (تفادي فتح منطق القرار 2 الحسابي بلا طلب صريح).

## اختبار قبل أي تعديل مستقبلي

يحتاج خادمًا محليًا يخدم **جذر المستودع** (المسارات النسبية للوحدات تتجاوز
مجلد الصفحة نفسها إلى `src/calibration/` و`src/ui/pages/06-library-export/`):

```bash
python3 -m http.server 8934 --directory /path/to/miran-platform
node src/ui/pages/07-settings-sync/tests/page-smoke.test.mjs
```

## لم يُبنَ بعد (خارج نطاق هذي المرحلة)

- تحكّم تفاعلي لتعديل حدود السماحية — عرض فقط حاليًا.
- ربط الصفحة الرئيسية (#1) بحالة المزامنة (نجاح/فشل آخر إرسال) في ملخص
  التقدّم — لم يُطلب صراحة بعد.
- مؤشر بصري واضح أثناء محاولة الإرسال نفسها (spinner/تعطيل الأزرار مؤقتًا)
  — الحالة تُحدَّث بعد اكتمال المحاولة فقط حاليًا، لا أثناءها.
